# План: Настройка списка разрешенных сайтов для расширения

## Текущая ситуация
- Расширение работает на всех сайтах (`matches: ["*://*/*"]` в manifest.config.ts)
- Нужно ограничить работу расширения списком разрешенных сайтов
- По умолчанию доступен только https://novelbin.com/

## Краткий план реализации

### 1. Создание хранилища для списка сайтов
- Использовать `chrome.storage.sync` для хранения списка разрешенных сайтов
- Структура данных: массив URL-адресов
- Значение по умолчанию: `['https://novelbin.com/']`

### 2. Создание компонента accessSites.vue
- Компонент для управления списком сайтов
- Функционал:
  - Отображение текущего списка разрешенных сайтов
  - Добавление нового сайта (input + кнопка)
  - Удаление сайта из списка
  - Валидация URL при добавлении
- Типизация: интерфейс для структуры данных сайта
- Использование composable для работы с chrome.storage

### 3. Интеграция в action-popup/pages/index.vue
- Импортировать и использовать компонент accessSites.vue
- Отобразить список сайтов в существующей разметке

### 4. Логика проверки доступа в content-script
- При загрузке content-script проверять текущий URL
- Получать список разрешенных сайтов из chrome.storage
- Сравнивать текущий URL со списком
- Если сайт не в списке — не монтировать overlay
- Использовать pattern matching для проверки (поддержка wildcards)

### 5. Создание composable для работы с сайтами
- Файл: `src/composables/useAccessSites.ts`
- Функции:
  - `getAccessSites()` — получение списка
  - `addAccessSite(url)` — добавление сайта
  - `removeAccessSite(url)` — удаление сайта
  - `isCurrentSiteAllowed()` — проверка текущего сайта
- Полная типизация всех функций и возвращаемых значений

### 6. Обновление manifest (опционально)
- Рассмотреть возможность динамического обновления `content_scripts.matches`
- Или оставить `matches: ["*://*/*"]` и делать проверку внутри скрипта

## Технические детали

### Структура данных
```typescript
interface AccessSite {
  url: string
  enabled: boolean
  addedAt: number
}
```

### Storage key
- Ключ: `ACCESS_SITES`
- Тип: `chrome.storage.sync`

### Pattern matching
- Использовать простое сравнение по началу URL
- Или регулярные выражения для более гибкой проверки
- Поддержка wildcards: `*.novelbin.com`

## Порядок реализации

1. Создать composable `useAccessSites.ts`
2. Создать компонент `accessSites.vue`
3. Интегрировать компонент в `index.vue`
4. Добавить проверку в `content-script/index.ts`
5. Тестирование на разных сайтах
6. Убедиться, что на https://novelbin.com/ работает по умолчанию
7. Убедиться, что на других сайтах overlay не появляется

## Требования по гайдлайнам
- Все ref/computed с типами
- Все функции с return type
- Без `any` и `as Type`
- Использовать type guards
- Семантические теги в компоненте
- Структура компонента: props → composables → state → computed → methods
- Использовать shadcn + tailwind для стилизации
