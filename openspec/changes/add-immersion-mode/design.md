# Design: режим вкраплений

## Context

Сейчас content script умеет один сценарий: страница на изучаемом языке →
`analyzeText` находит сложные слова → `utils/highlight.ts` подсвечивает их,
`WordCard.vue` показывает карточку. Словарь (`DictionaryEntry`) уже несёт
SRS-поля (`dueAt`, `intervalStep`, `reviews`, `lapses`), лестница интервалов
и выбор «что пора повторить» лежат в `utils/srs.ts` (`reviewEntry`,
`dueEntries`) — чистые функции без DOM. Поиск слов в тексте с границами слова
и группами уже решён в `utils/terms.ts` (`buildTermsPattern`).

Режим вкраплений — обратный сценарий: страница на языке перевода (родном),
в текст вкрапляются слова изучаемого языка из словаря пользователя.

## Goals / Non-Goals

**Goals:**

- Чтение родных страниц двигает SRS-прогресс словаря без открытия тренировки.
- Работает полностью офлайн: только записи словаря, ни модели, ни внешних словарей.
- Тот же визуальный язык: подсветка и карточка не отличаются от разбора.
- Выключенный режим не оставляет следов на странице.

**Non-Goals:**

- Вкрапление слов, которых нет в словаре пользователя (Toucan-режим «выучи
  новое слово из частотного списка» — отдельная фича, если понадобится).
- Морфологический анализ русского текста (см. Decisions, упрощение).
- Изменения тренировки и её лестницы интервалов.
- Автоперевод страниц и любые сетевые вызовы.

## Decisions

**1. Замена, а не показ рядом.** Словоформа родного текста заменяется изучаемым
словом (`работой` → `job`), оригинал живёт в карточке по наведению и в
`data`-атрибуте метки. Показ рядом («работой (job)») дублирует текст, ломает
ритм чтения и не заставляет вспоминать значение — теряется тренировочный эффект.

**2. Переиспользуем механизм подсветки.** Вкрапление — та же метка, что у
подсветки (`utils/highlight.ts`), с инлайн-стилями и цветом «уже в словаре»;
разница только в том, что текст внутри метки — не оригинал узла, а слово из
словаря. Оригинал сохраняется в атрибуте метки, выключение режима возвращает
его на место. Инвариант «не подключаем стили к документу и не ломаем вёрстку»
сохраняется: меняется содержимое текстовых узлов и ничего больше. Не трогаем
узлы внутри ссылок, `pre/code`, полей ввода и contenteditable.

**3. Сопоставление — новый чистый модуль `utils/immersion.ts`.** Вход: текст
страницы + записи словаря; выход: список «словоформа в тексте → запись».
Совпадение: словоформа равна `translate` записи либо делит с ним основу
(общий префикс ≥ 4 символов, расхождение хвостов ≤ 3 символов — покрывает
большинство русских окончаний). `buildTermsPattern` тут не подходит: он
экранирует термины и ищет точные альтернативы, префиксное правило им не
выразить. Вместо регэкспа — токенизация текста по `\p{L}+` и сравнение
токенов с `translate`: границы слов даёт сама токенизация.
Морфологии нет сознательно: библиотека лемматизации тяжелее
всей фичи; упрощение фиксируется в `deferred.md` с триггером «совпадений
заметно меньше, чем слов в словаре».

**4. Приоритет и плотность.** Кандидаты сортируются: сначала `dueEntries`
(пора повторять), затем ни разу не тренированные, затем остальные. На страницу
вкрапляется не больше 15 слов и не больше одного вкрапления на предложение
(границы предложений — существующий `utils/sentence.ts`): страница должна
остаться читаемой. Одна запись словаря вкрапляется один раз за страницу.

**5. Самооценка в карточке.** `WordCard.vue` получает режим вкрапления: показывает
оригинал (словоформу из текста), перевод-объяснение из записи и кнопки
«знал / не знал». Ответ идёт через `useDictionary` в `reviewEntry` — та же
функция, что в тренировке. После ответа метка раскрывается в оригинал:
слово за сессию чтения спрашивается один раз.

**6. Включение — явное, условие — автоматическое.** Настройка
`readerSettings.immersion` (по умолчанию выключена) + кнопка в шапке оверлея.
При включённой настройке режим срабатывает только если собранный текст страницы
действительно на языке перевода (`readerSettings.targetLang`): доля символов
алфавита языка перевода > 60 % (для пары ru/en это дешёвая проверка по
диапазонам юникода). Проверка различает только пары с разными письменностями —
при совпадающих (например, en → es) режим автоматически не включается вовсе:
иначе английская страница прошла бы порог латиницы и вкрапления подменили бы
обычный разбор. Страница на изучаемом языке идёт обычным разбором — развилка
в одном месте, рядом с вызовом `analyzeText` в оверлее.

## Risks / Trade-offs

- [Омонимия перевода: «мир» вкрапится как `peace`, когда в тексте «мир» = world]
  → карточка всегда показывает оригинал из текста; неверные вкрапления не пишут
  ошибку в SRS автоматически — прогресс двигает только явный ответ пользователя.
- [Префиксное сопоставление промахивается на супплетивных формах («люди» ↔
  «человек»)] → сознательная потеря полноты; триггер в `deferred.md`.
- [SPA перерисовывает DOM и стирает вкрапления] → тот же механизм, что у
  подсветки: опрос адреса в `content-script/index.ts` пересоздаёт оверлей,
  разбор повторяется. Ничего нового не строим.
- [Замена текста на сайте с динамическим редактированием (формы, комментарии)]
  → вкрапления не ставятся в редактируемые области и рядом с полями ввода.
- [Пользователь читает не по-русски, а алфавит тот же (украинский)] → кириллица
  пройдёт порог, а совпадений со словарём почти не будет — вкрапления просто
  не появятся; при сомнении режим не срабатывает — ложное молчание дешевле
  ложной замены. Пары с общей письменностью (en → es) отключены на уровне
  детекции (Decision 6).

## Migration Plan

Миграций нет: новая настройка с выключенным дефолтом, структура словаря не
меняется. Откат — выключить настройку; страницы восстанавливаются перезагрузкой
или снятием меток.

## Open Questions

- Нужна ли отдельная секция вкраплённых слов в панели оверлея или списка
  на странице достаточно (в MVP панель не меняем).
- Порог плотности (15 слов) и порог алфавита (60 %) — константы до первых
  жалоб; выносить в настройки не планируем.
