# Erudit — состояние проекта

Расширение помогает читать тексты на иностранном языке: разбирает страницу через LLM,
показывает сложные слова с переводом, подсвечивает их в тексте и складывает в словарь.
Языковая пара настраивается, интерфейс есть на русском и английском.

## Готово

- **Список разрешённых сайтов** (`useAccessSites`, `storage.sync`, по умолчанию `reddit.com`).
  Content script монтируется только на разрешённых адресах. Матчинг адресов — `matchesSite`,
  покрыт тестами (протокол, хост, `*.` поддомены, префикс пути).
- **Оверлей страницы** в Shadow DOM: собственный контейнер справа снизу, сворачивание, закрытие.
  Стили инлайнятся внутрь shadow root, стили PrimeVue зеркалятся из `document.head`
  (`mirrorStyles.ts`) — документ сайта не трогаем.
- **Разбор текста страницы** (`pageText.ts` + `utils/extract/`) — три источника по убыванию
  доверия: выбранная пользователем область → правило для сайта → скоринг по плотности текста.
  Правила есть для reddit, webnovel, royalroad; скоринг штрафует за долю текста
  в ссылках, отсекая меню и «читайте также». Чистые части (`blocks`, `rules`, `score`)
  вынесены из DOM и покрыты тестами.
- **Ручной выбор области** (`areaPicker.ts`): кнопка в шапке оверлея, наведение подсвечивает
  блок, клик запоминает CSS-селектор для домена (`useAreaSelectors`, `storage.local`).
- **Языковая пара и уровень** (`useReaderSettings`, `storage.sync`): «читаю на» (по умолчанию
  английский), «перевод на» (язык браузера) и уровень CEFR. Всё уходит в промпт; языки
  подставляются и в запросы словарей, и в ссылки на внешние переводчики (`utils/languages.ts`).
- **Уточнение к промпту**: произвольный текст из настроек уходит в системное сообщение
  после наших правил и обрезается по лимиту — JSON-контракт ответа остаётся нашим.
- **Провайдеры модели** (`utils/llm/providers.ts`): OpenAI-совместимый API, Anthropic Messages
  и Google Gemini. У каждого своя пара чистых функций «собрать запрос / достать текст»,
  транспорт общий; переключение вида API подставляет адрес и модель. Совместимые облака
  (OpenAI, OpenRouter, Groq, DeepSeek, Mistral) — кнопки-пресеты, а не отдельные провайдеры.
- **Машинный перевод** (`utils/mt/translators.ts` + `mtClient.ts`): DeepL и LibreTranslate.
  Порядок источников в `translateTerm` — словарь, переводчик, модель.
- **Интерфейс на шести языках** (`utils/i18n.ts`, локали в `src/locales/`): английский,
  русский, испанский, португальский, китайский и корейский. Vue-i18n в режиме Composition API,
  язык в `storage.sync`, смена без перезагрузки. По умолчанию берётся язык браузера
  (`defaultUiLanguage` в `utils/languages.ts`), незнакомый — английский, он же fallback
  для пропущенного ключа. Формы числительных: русскому нужно три (свои `pluralRules`
  поверх `utils/plural.ts`), европейским хватает двух, у китайского и корейского ветки `|`
  просто нет. Совпадение наборов ключей во всех локалях проверяет `locales.test.ts`.
  Тексты ошибок тоже в локалях; `anki.ts` бросает код ошибки, а не текст, — он тестируется
  в node и о локалях не знает.
- **Запрос к LLM** через background-прокси (`bgFetch` → `browser.runtime.sendMessage`):
  content script не может ходить на http-эндпоинт со https-страницы, service worker может.
- **Разбор ответа модели** (`llmParse.ts`): переживает markdown-фенсы и рассуждения вокруг
  JSON, нормализует уровень CEFR, тесты в `llmParse.test.ts`.
- **Внешние словари** (`dictClient.ts`, `utils/dict/`): раскрытие карточки показывает перевод
  из Яндекс.Словаря (нужен бесплатный ключ, `useDictSettings`) и толкование с примером из
  dictionaryapi.dev (без ключа), плюс ссылки на Google, Яндекс, Reverso, Мультитран
  и Wiktionary. Отказ одного словаря не отменяет ответ другого, ответы кэшируются в памяти.
  Разбор ответов — чистые функции с тестами на реальной структуре обоих API.
- **Офлайн-уровни CEFR** (`utils/cefr/`): 8833 английских слова и словосочетания из CEFR-J
  Vocabulary Profile (A1–B2) и Octanove Profile (C1/C2), собранные `scripts/buildCefrList.mjs`
  в `wordLevels.data.ts` (75 КБ, отдельный чанк, грузится динамическим импортом при первом
  обращении). Список работает как страховка: слово, которое он относит строго ниже уровня
  читателя, из ответа модели выбрасывается, а уровень слова, переведённого словарём или
  машинным переводчиком, берётся оттуда же. Уровень от модели не перебивается — она видит
  контекст, список нет. Формы слов снимаются правилами (`cefr/forms.ts`, с тестами).
  Только для `sourceLang === 'en'`; профиль для другого языка заводится по
  `docs/cefr-profiles.md`.
- **Пояснение к слову** — отдельным запросом к модели с контекстом страницы, по кнопке внутри
  раскрытой карточки: само раскрытие ничего не стоит.
- **Перевод выделенного**: одиночное слово переводит словарь, фразу — модель
  (`translateTerm.ts`, переключатель в настройках). Уровень CEFR ставит только модель.
  Что происходит при выделении, выбирается в настройках (`selectionMode`): карточка
  с переводом сразу, кнопка-предохранитель с логотипом (перевод по клику — запрос
  не уходит на случайное выделение), сохранение одним действием или ничего.
- **Карточка слова** (`overlay/components/WordCard.vue`) — одна на подсказку при
  наведении и на выделение: слово, уровень, перевод, за ним транскрипция и толкование
  из словарей (запрос через 400 мс после появления, ответы кэширует `dictClient`),
  внизу — строка «найдено на этой странице» или «уже в словаре, повтор через N дней»
  (`dueInDays` в `srs.ts`). Данные для наведения берутся из живых списков слов
  и словаря, а не из атрибутов подсветки: статус меняется сразу после сохранения.
- **Переход к слову в тексте** (`revealTerm` в `highlight.ts`): клик по слову
  в оверлее или кнопка-прицел прокручивает страницу к вхождению и подсвечивает его
  на полсекунды инлайновым стилем. Повторный клик ведёт к следующему вхождению.
- **Подсветка в тексте страницы** двумя цветами (`highlight.ts`, инлайновые стили):
  жёлтым — новое, зелёным — то, что уже в словаре. Сохранённые слова ищутся по всей
  странице, независимо от разбора страницы, и из списка нового исчезают. Поиск идёт одним
  общим регулярным выражением на все термины (`terms.ts`) — словарь может вырасти
  до тысяч слов, а проход по тексту остаётся один.
- **Словарь** (`useDictionary`, `storage.local`): запись хранит слово, перевод,
  предложение-контекст, пояснение, уровень и время. Контекст для выделенного текста
  снимается с ближайшего абзаца (`contextAround` в `useTextSelection`) — это бесплатно
  и точнее поиска по разобранному тексту, который нашёл бы первое вхождение слова
  где угодно; для слов из списка он по-прежнему ищется в тексте страницы. Три входа — кнопка-закладка в списке слов,
  выделение текста на странице (плавающая кнопка + отдельный запрос перевода),
  ручная форма на экране словаря.
- **Скрытые слова** (`useIgnoredWords`, `storage.local`): кнопка с глазом в оверлее убирает
  слово из списка и из подсветки навсегда — для имён, терминов и давно знакомого. Список
  отдельный от словаря: в словаре такие слова попали бы в тренировку и в экспорт.
  Вернуть можно на экране словаря.
- **Экран словаря** (`/options-page/dictionary`): поиск по слову, переводу и пояснению,
  фильтр по уровню и по наличию пояснения, сортировка по дате и алфавиту, правка перевода
  и удаление. Удаление мягкое, поэтому внизу экрана — список удалённых с кнопкой возврата
  (`restoreEntry`, прогресс тренировки возвращается вместе со словом) и «Очистить»,
  которая выбрасывает надгробия совсем. Логика фильтрации — `utils/dictionary.ts`, без браузерных API, с тестами.
- **Тренировка** (`/options-page/training`): карточка со словом и контекстом, перевод
  по кнопке, самооценка «знал / не знал». Интервалы 1, 3, 7, 16, 35, 90 дней, ошибка
  сбрасывает лестницу целиком (`srs.ts`, с тестами). Сессия — 20 слов.
- **Экспорт в Anki** (`anki.ts`): колода `.apkg` — zip с базой SQLite схемы 11, собирается
  через sql.js прямо в браузере. Четыре поля (слово, перевод, контекст, пояснение),
  уровень уходит в теги, `guid` берётся из id записи — повторный экспорт обновляет
  заметку, а не плодит дубли. Выгружается то, что видно на экране с учётом фильтров.
  Проверено живым Anki.
- **Импорт из Anki** (`parseApkg` там же): `.apkg` разбирается обратно — первые два поля
  заметки идут в слово и перевод, третье в контекст, уровень берётся из тегов. Дубли
  отсекает `addEntry`. Новый формат `collection.anki21b` (zstd) не поддержан.
- **Режим вкраплений** (в интерфейсе — «Подмена слов»; `utils/immersion.ts` с тестами, развилка в `analyze`
  у `ChapterOverlay`): на странице на языке перевода отдельные словоформы заменяются
  словами из словаря — сначала те, что ждут повторения по SRS. Карточка по наведению
  показывает оригинал и кнопки «знал / не знал», ответ двигает запись той же лестницей,
  что тренировка. Работает офлайн, включается на своём экране «Подмена слов»
  (`pages/immersion.vue`: тумблер, механика по шагам, ограничения) и кнопкой в шапке
  оверлея. Язык страницы определяется долей букв письменности языка перевода (> 60 %);
  пары с общей письменностью (en → es) не различаются — режим молчит.
- **Настройки** (options page) — четыре подраздела в меню, каждый со своим роутом:
  «Чтение» (`pages/index.vue`: язык интерфейса, языковая пара, уровень, автозапуск разбора,
  реакция на выделение текста, уточнение к промпту), «Модель» (`pages/model.vue`: пресеты, вид API, адрес, имя модели,
  ключ, проверка подключения), «Словари» (`pages/dictionaries.vue`: ключ Яндекс.Словаря,
  приоритет словаря, машинный переводчик и его ключи), «Сайты» (`pages/sites.vue`).
  Любой OpenAI-совместимый API, включая Yandex AI Studio
  (`https://llm.api.cloud.yandex.net`, модель `gpt://<каталог>/yandexgpt/latest`) — пресеты
  есть в настройках. Ключи для dev-сборки берутся из `.env`, в прод-сборку не попадают.
- **Проверка подключения** (`checkModel` в `llmClient.ts`): кнопка в разделе «Модель»
  шлёт короткий запрос выбранному провайдеру и показывает время ответа или ту же
  ошибку, что увидел бы оверлей. Рядом, в меню, у пункта «Модель» горит точка, когда
  адрес облачный, а ключ пуст (`utils/settingsStatus.ts`, с тестами).
- **Вход в словарь** — из шапки оверлея и первой кнопкой в попапе (`utils/dictionaryTab.ts`).
  Вкладку открывает background по сообщению `ui/open-dictionary`: в content script
  `browser.tabs` нет, а адрес не передаётся — страница сайта не должна уметь открывать
  через расширение произвольные адреса.
- **Попап**: сводка по активным сайтам, вход в словарь и кнопка «Разрешить <домен>» —
  адрес берётся из открытой вкладки (`tabs.query`), покрытие проверяется тем же
  `matchesSite`, что и в content script.
- **UI**: PrimeVue + Tailwind 4, компоненты автоимпортируются, тема через класс `.dark`.

## Дальше

Отложенное с триггерами возврата — `deferred.md`. Ближайшее оттуда:

1. **Источник слова** (сайт, заголовок, ссылка) — без него нет фильтра «слова из этого источника».
2. **Уровень CEFR для слов из словаря** — сейчас он есть только у того, что перевела модель.
3. **Общий репозиторий селекторов** — правила `host → селектор` списком, как у блокировщиков.

## Ограничения и решения

- **Shadow DOM обязателен.** Раньше content script импортировал глобальный `base.css`
  с Tailwind-preflight — это ломало вёрстку сайта. Никакого глобального CSS в документ.
- **PrimeVue Dialog в оверлее не используется**: он телепортируется в `document.body`,
  то есть за пределы shadow root, и остаётся без стилей. Панель свёрстана вручную.
- **PrimeVue 4.5 не умеет `styleContainer`** — отсюда зеркалирование стилей из head.
- **Словарь в `storage.local`, настройки в `storage.sync`.** У `sync` лимит 100 КБ на всё
  и 8 КБ на запись — словарь туда не влезает. Плата: словарь не синхронизируется
  между устройствами.
- **`useBrowserStorage` не умеет хранить `Record`**: `mergeDeep` идёт по ключам дефолта
  и у пустого объекта вычистит всё сохранённое. Для словарей «ключ → значение» —
  массив записей, как в `useAreaSelectors`.
- **WASM требует своей CSP.** sql.js для экспорта в Anki — это WebAssembly, а политика
  расширения по умолчанию его не пускает: в манифесте прописан
  `script-src 'self' 'wasm-unsafe-eval'` для страниц расширения.
- **Ключи и адреса — только в настройках**, не в коде: репозиторий публичный.
