## 1. Типизация

- Все `ref` и `computed` должны быть **с типами**.
    - пример: const currentSortLabel = computed<string>(() => {...});
    - const someRef = ref<string>('some string');

- Все функции должны иметь указанный **return Type**.
    - Если ничего не возвращает → тип `void`.
- Запрещено использовать **`as Type`**, только **type guards**.
- Не писать избыточные аннотации типов для переменных, когда тип однозначно выводится. Например, вместо `const total: number = hasProperty(payload, 'total') ? payload.total : 0;` — писать `const total =  ? payload.total : 0;`.

## 3. Верстка

- Использовать **семантические теги**.
- Для списков → только `<ul>/<ol>`, не `<div>`.
- Для кнопок → только `<button>`, не `<div>/<span>`.

## 4. Vue-компоненты

### Структура объявления переменных:

1. props
2. composables
3. state
4. computed
5. watchers
6. lifecycle
7. методы

### Правила:
- `ref` на DOM/компоненты именовать через **`$`**.
- Имена функций должны быть **глагольными** (например, `fetchUsers`).

### Оптимизация:
- Минимизировать количество `watch` → использовать `computed`.
- Избегать тяжёлых вычислений в `computed` без мемоизации.
- Не использовать `v-if` и `v-for` одновременно → разделять.
- Всегда использовать **ключи (`:key`)** в `v-for`.
- Все `props` должны быть с **типами и дефолтами** (если не обязательны).
- Избегать лишнего `reactive` → использовать `ref`, если хранится одно значение.
- Глобальные стейты (**Pinia**) → только при реальной необходимости,  
  локальный state в приоритете.
- Не хранить в `ref/reactive` данные, которые можно вычислить (**computed**).

## 6. Чистота кода

- Не усложнять: избегать излишних проверок, прослоек и громоздких конструкций. Предпочитать простые и явные решения, если они покрывают требования. Не вводить лишние type guards/utility-функции, если они не дают реальной пользы. При этом типобезопасность сохранять: без `any` и без `as Type`.
- Магические числа и строки выносить в **константы**.
- Функции длиннее **30–50 строк** разбивать на меньшие.
- Комментарии писать только в крайне редких случаях, когда есть очень не очевидная логика, в стилях не нужно комментировать впринципе.
- Импортировать только то, что используется → запрет "мертвого" кода.
- Не использовать **`any`**, всегда уточнять типы.
- Если функцию можно написать в 1–3 строки, использовать стрелочную функцию; в остальных случаях — объявление через `function`.
- Удалять неиспользуемые переменные и **`console.log`** перед коммитом.
- По коду следовать структуре указанной в docs/DEVELOPMENT.md

## 7. Безопасность

- Никогда не использовать `v-html` без строгой фильтрации.
- Все внешние ссылки открывать с `rel="noopener noreferrer"`.
- Данные из API всегда валидировать перед использованием.
- Не хранить секреты (ключи, токены) в коде.
- Проверять **user input**, избегать XSS-инъекций.
