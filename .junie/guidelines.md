# Руководство проекта для Junie

Данный документ описывает обязательные правила разработки и проверки кода в этом репозитории. Все пункты применимы ко всем PR и коммитам. Рассуждения, планирование и отчеты Junie должны быть на русском языке.

## Доп правила лежат в .github/

## 1. Типизация

- Все `ref` и `computed` должны быть с указанием типов.
  - Примеры:
    - `const currentSortLabel = computed<string>(() => { /* ... */ })`
    - `const someRef = ref<string>('some string')`
- Все функции должны иметь явно указанный возвращаемый тип.
  - Если функция ничего не возвращает → `void`.
- Запрещено использовать приведение вида `as Type`. Использовать только type guards и сужение типов.
- Не использовать `any`. Типы должны быть уточнены.

## 2. Стилизация

- Уникальные классы использовать только в `<style scoped>`.
- Запрещены inline-стили и `!important`.
- Имена классов писать по БЭМ.
- Не хардкодить цвета/отступы — использовать переменные/токены/классы утилит.

## 3. Верстка

- Использовать семантические HTML-теги.
- Для списков — только `<ul>/<ol>`, а не `<div>`.
- Для кнопок — только `<button>`, а не `<div>/<span>`.

## 4. Vue-компоненты

Структура объявления переменных:

1. props
2. composables
3. state
4. computed
5. watchers
6. lifecycle
7. методы

Правила:
- Ссылки на DOM/компоненты в `ref` именовать через префикс `$`.
- Имена функций должны быть глагольными (например, `fetchUsers`).

Оптимизация:
- Минимизировать количество `watch`, предпочтительно использовать `computed`.
- Избегать тяжёлых вычислений в `computed` без мемоизации.
- Не использовать одновременно `v-if` и `v-for` — разделять узлы.
- Всегда указывать ключи (`:key`) в `v-for`.
- Все `props` должны иметь типы и дефолты (если не обязательны).
- Избегать лишнего `reactive` — использовать `ref`, если хранится одно значение.
- Глобальные стейты (Pinia) — только при реальной необходимости, локальный стейт в приоритете.
- Не хранить в `ref/reactive` данные, которые можно вычислить (`computed`).

## 6. Чистота кода

- Магические числа и строки выносить в константы.
- Функции длиннее 30–50 строк разбивать на меньшие.
- Комментарии писать только при действительно неочевидной логике; в стилях не комментировать.
- Импортировать только используемое — запрет «мертвого» кода.
- Не использовать `any`, всегда указывать точные типы.

## 7. Безопасность

- Не использовать `v-html` без строгой фильтрации.
- Все внешние ссылки открывать с `rel="noopener noreferrer"`.
- Данные из API валидировать перед использованием.
- Не хранить секреты (ключи, токены) в коде.

## 9. Язык

- Все рассуждения, планирование и отчеты Junie — на русском языке.

- Вносить минимально необходимые изменения для выполнения задачи.
- После правок запускать релевантные проверки/скрипты проекта (если есть) и фиксировать статус через `submit`.
